# Calendar surface census

**Status:** reference, 2026-10-13

Every place Tempo's implementation touches a calendar, in the tree this file is committed with, written by `scripts/calendar_census.py`. It is the evidence for [calendar-surface.md](calendar-surface.md), which is the plan and holds the counts of the first census, at `254923c`; this file tracks no work. Nothing here is sampled: the script reads every file of `lib/` and writes every match, and a table is regenerated by running it again.

## What was read, and how

* **110 files of `lib/`** — 82,985 lines: 46,061 of code, 14,905 of documentation (`@doc`, `@moduledoc` and `@typedoc`, doctests among them), 11,795 of comment and 10,224 blank. Only code is counted below: a calendar named in a doctest or a comment is no code path.

* **A call on a calendar** — every `receiver.function(` whose receiver is a variable, every `&receiver.function/arity` and every call on the result of a call. The receiver of every one is `calendar`, a call of `Tempo.Calendars` or of a function named for a calendar, `backend`, `resolver`, `clock()` or `database()`; the first three are a calendar, and the others are not.

* **A calendar named** — every module name in a line of code, with the file's aliases resolved, that is one of `Calendar.ISO`, `Calendrical.Gregorian`, `Calendrical.ISOWeek` and `Calendrical.Chinese`. No other calendar module is named in code.

* **A probe** — every `function_exported?/3`, and every call of a private `exported?/3`, which is the same question (`Tempo.UnitValues` had one until its last call became a callback).

* **A decider** — a function that answers by what kind of calendar it is given. They were found by reading every predicate whose head names a calendar (64), every line that names a calendar and every probe, and each is listed with where it is defined and every call of it.

* **Two columns are a reading** — the class of a line that names a calendar and of a line that holds a calendar number were read a line at a time, first at `254923c`. One the script finds with no reading is written `unread`.

## 1. Calendars named in code

0 lines name a calendar module, and 0 names are on them, a line that names two calendars counting two. Each line has one class:

* **D** (0) — Default: no calendar given is the Gregorian.

* **I** (0) — `Calendar.ISO` read as the Gregorian, or written back as it, at the boundary.

* **F** (0) — Fast path: the Gregorian is answered without asking it, where the general path would give the same answer.

* **S** (0) — Special case: the Gregorian, or another named calendar, is given other behaviour than the rest.

* **G** (0) — A computation done in the Gregorian by naming it, where any calendar could be asked.

* **W** (0) — `Calendrical.ISOWeek` paired with the Gregorian for ISO 8601 week dates.

* **X** (0) — The Gregorian as the calendar of something outside Tempo: the zone database, Astro, RFC 5545, cron.

* **T** (0) — Text: the calendar's name is left out of what is written for a Gregorian value.

## 8. Every constant Tempo defines

246 module attributes are constants: every one that is not a doc, a spec or a directive. Each was read, with its whole value, and has one class. A constant is a sign that Tempo holds what it could ask, so each class says why its constants are Tempo's own to hold, but for the first, whose constants are not.

* **calendar** (0) — What a calendar would answer, or a calendar named. To go.

* **units** (92) — Tempo's own units, their order and the places they are written in.

* **clock** (34) — ISO 8601's time of day: the hours of a day, the minutes of an hour, the seconds of a minute and their fractions.

* **standard** (26) — A table or a number of a notation or a standard Tempo reads or writes.

* **limit** (34) — A bound Tempo sets on its own work: how much it reads, lists or walks before it stops or asks.

* **key** (2) — A key Tempo keeps something under.
